# Mobile data navigation and system-bar follow-up

## Root causes and corrections

The earlier loading boundaries improved feedback but did not preload dynamic page data. Each tab still needed a server round trip and sometimes a subsequent JavaScript chunk request. In a controlled local production run (150ms network latency, 2Mbps download, CPU slowed 4x), those data requests took roughly 180–240ms, with additional rendering/chunk waits. A read-only production `/results` check from the server took 16ms directly and 61ms through public HTTPS; this is not an authenticated-screen or real-phone latency measurement.

Only the visible, inactive bottom tabs now explicitly preload full route data. The pinned Next version requires a minimum 30-second static/prefetch lifetime, so `staleTimes.static` is 30 and ordinary dynamic navigation remains at zero. This cache belongs to the current browser session, not a shared server cache. Successful writes invalidate the actual competition, studio, participant and results routes; old `/admin`, `/e` and ID-as-slug invalidations were corrected. Logout reloads the document, role preview changes invalidate the client cache, and native resume refreshes unless a form is dirty. Back/Forward restoration and shared layouts follow Next's separate lifetime rules; the 30 seconds is not a universal freshness guarantee. Live board polling remains unchanged.

Roster queries previously fetched every scoring input and zone definition even on registration/people screens. Lean, permission-scoped roster queries now fetch only the required fields, detail queries select one team, and result details serialize one row. Wave reads reuse one snapshot and read again after a clock transition. On a local 108-team dataset (median of five reads), roster work fell from 8 to 5 SQL calls and from 160,875 to 108,841 serialized bytes; one-team detail returned 1,044 bytes. Wave reads fell from 6 to 4 SQL calls. These query measurements do not claim a matching end-to-end speedup.

Android Capacitor 8 supplies `--safe-area-inset-*` variables, which the old CSS ignored. Native safe areas now protect the entire document, including login, public results, errors and loading. iOS uses the official StatusBar height when WebKit's inset is missing; zero/unavailable measurements retain a conservative legacy fallback. Headers and fullscreen dialogs have their own correctly offset viewports. PlainHeader carries its own spacer so a hidden, retained Next screen cannot change the new screen's offset. Bottom navigation also follows the active route's owner rather than retained DOM; the board chooses its own contextual/personal navigation. The read-only preview and its exit button remain below the fixed header.

Native configuration also removes Android's competing `Keyboard.resizeOnFullScreen` workaround, explicitly lets SystemBars manage CSS insets and enables the iOS view-controller status-bar setting required by Capacitor. These configuration changes require a rebuilt installed app. The CSS and runtime measurement changes reach existing shells via the live website.

## Validation and test builds

- Full local `npm run verify` passed: types, lint, 284 tests and production build. This workspace includes 21 unrelated Play publishing tests that are deliberately excluded from this release. Final test-only edits also passed lint/type checks.
- Final focused browser runs passed: full-data warming 4 cases; permissions/data scope 7; cold loading/back restoration 7; measured iOS/Android inset simulation 16; board navigation across four roles on mobile and desktop 3. Five inapplicable combinations were explicitly skipped, not counted as passing.
- The inset run checked Chromium English/dark and WebKit Arabic/light at 390px. The board run also checked 1024px desktop and the simulated native tablet branch. This follow-up does not claim a fresh complete 96-project matrix or physical-device run.
- Production browser regression verifies actual wave data is present before a tap, no new data request is required for a warm tab, and a fresh request occurs after the 30-second lifetime. Both admin and studio pass on Chromium and WebKit.
- In the local throttled navigation sample, mobile warm tabs painted in 127–342ms versus 499–1,146ms before. All ten measured mobile transitions needed no new route data request at tap time. This is a controlled local sample, not a real-device or production-network guarantee; prefetching moves work earlier and does not remove cold-load latency. Timing evidence is in `.mobile-qa/data-profile-before.json` and `data-profile-after.json`.
- Safe-area tests simulate the native API independently of App/Keyboard availability, Android inset variables, orientation/resize, scroll, all page-shell types, fullscreen dialogs and retained hidden screens. Browser simulation does not replace device testing.
- Local query traces and browser reports stay in ignored `.mobile-qa/`; no sessions or fixture credentials are published.
- For local production QA, start the production server and HTTPS proxy before Playwright and set `MOBILE_QA_PRODUCTION=1` and `MOBILE_QA_URL` to that proxy. Build with its canonical `NEXT_PUBLIC_APP_URL`/`NEXTAUTH_URL`, or map only the fixture's localhost redirect origin in the local proxy. The final preview-exit check verifies the real 307 response, cleared preview cookie, root navigation and disappearing banner.
- `npm run mobile:sync` updates both native shells. Local Android compilation needs JDK 21/Android SDK; this workstation currently has neither available. iOS compilation requires macOS/Xcode.
- The manual `mobile-checks` workflow builds a debug Android APK and unsigned iOS simulator app without signing credentials or store uploads. These are compilation artifacts, not a production-store submission. The simulator ZIP cannot be installed on a physical iPhone.
- A signed iOS test build and actual iPhone/iPad/Android checks remain necessary before declaring device-level validation complete. Existing store publishing workflows are not triggered by this follow-up.

Official platform references: [SystemBars](https://capacitorjs.com/docs/apis/system-bars), [StatusBar](https://capacitorjs.com/docs/apis/status-bar). Next behavior was checked against the documentation bundled with the installed 16.3.4 package and the full-prefetch implementation; full dynamic prefetch requests omit the partial-prefetch header.
